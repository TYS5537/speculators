# Qwen3-4B: DSpark and bestarch MMuse optimizer comparison

Edit `settings.sh` for model/data paths, NPUs, endpoint and the shared MMuse architecture. All three use the existing Speculators trainer and the original bestarch data/batch budget. DSpark overrides only peak LR, weight decay, scheduling and attention through shell arguments; both MMuse scripts also use full attention in all five draft layers. This is not a full paper reproduction. Run the entrypoints with Bash from any directory; relative configured paths are interpreted from the repository root. Keep this directory beside `../common/`; copy the whole directory, not one entrypoint. The existing 8B and upstream examples are unchanged.

## Run

Start the target in a separate terminal, and leave it running:

```bash
bash examples/train/qwen3_4b_bestarch/server.sh
```

It uses Qwen3-4B, NPUs `0,1`, DP=2, port `8001`, and target layers `1 9 17 25 33`. The target does not need a draft checkpoint or optimizer setting. All three trainers can reuse it as long as target weights and extracted layers match. A compatible server already running on this port need not be restarted. Startup has a timeout and checks early process exit; provenance is saved per launch.

Run these **one at a time**, waiting for the prior training process to finish:

```bash
bash examples/train/qwen3_4b_bestarch/train_dspark.sh
bash examples/train/qwen3_4b_bestarch/train_mmuse_legacy_optimizer.sh
bash examples/train/qwen3_4b_bestarch/train_mmuse_upstream_optimizer.sh
```

All three trainers default to NPUs `2,3,4,5,6,7` (six training devices). Each prints its PID and log path. Do not paste all three commands at once: their training devices overlap. Check the training log for startup/runtime errors; printing a PID is not a successful training result. The worker count is derived from `TRAIN_NPUS`. Logs, TensorBoard events and checkpoints have separate per-experiment directories under `./output/qwen3_4b_bestarch`. Existing run directories are refused, not resumed or overwritten. Set a new `OUTPUT_DIR` to repeat an experiment. Training never owns or stops the shared target server.

## DSpark baseline: four script-only changes

`train_dspark.sh` launches the original `speculators.train` entrypoint with `--training-recipe legacy`, `--loss-implementation legacy` and `--muon-parameter-policy legacy`. There is no separate paper trainer and no change to shared Python defaults. Its output variant is `dspark_custom`.

| Setting      | Original baseline          | This DSpark script                           |
| ------------ | -------------------------- | -------------------------------------------- |
| Peak LR      | Muon 6e-4 / AdamW 6e-5     | Both 6e-4                                    |
| Weight decay | Muon 0.1 / AdamW 0.01      | Both 0                                       |
| Schedule     | Linear / default 1% warmup | Cosine / 4% warmup                           |
| Attention    | Sliding window 2048        | Full attention at draft layers 0, 1, 2, 3, 4 |

The script-local knobs are `DSPARK_LR`, `DSPARK_WEIGHT_DECAY`, `DSPARK_SCHEDULER_TYPE`, `DSPARK_WARMUP_RATIO` and `DSPARK_FULL_ATTENTION_INDICES`. Muon's LR is passed explicitly, so changing the base LR does not silently multiply it by ten. SDPA remains the attention backend.

Everything else stays on the original recipe: Muon + AdamW grouping (not all AdamW), `DATA_PATH` pointing to the original prepared 700k data, 3,072-token packed batches per card, no gradient accumulation (one update per packed batch), 90% training / 10% validation, ten epochs, seed 42, block 7, at most 512 anchors per packed row, five draft layers, rank-256 vanilla Markov + confidence, CE/TV=0.1/0.9, legacy teacher-argmax CE and loss normalization, position weighting `exp(-position/7)`, noise std 0.05, legacy initialization and precision/vocab policy.

There is no fixed global batch of 512 sequences and no device-divisibility check against 512. On six devices the text-token capacity is 6 * 3072 = 18,432 per update (including padding capacity, excluding synthetic draft anchor positions); the number of original samples varies with their lengths. No dataset or target responses are generated by these launchers. Losses, checkpointing, log frequency, validation and numerical precision continue to use the existing trainer.

These four choices do not make this a reproduction of DeepSpec's entire public training recipe, and DSpark vs MMuse is not an architecture-only ablation because their LR/decay/schedule differ. All three now use full attention.

## MMuse optimizer comparison

The two MMuse runs change only attention relative to the supplied bestarch: `MMUSE_FULL_ATTENTION_INDICES=(0 1 2 3 4)` applies full attention to all five draft layers, through the existing CLI. Their LR, weight decay and scheduling are unchanged and do not inherit the DSpark-specific overrides. They retain 3,072 tokens, 10 epochs, block 7, 512 anchors, 5 draft layers, SDPA, seed 42, CE/TV=0.1/0.9, and the legacy loss/initialization recipe. No data regeneration is performed. The prepared tokenizer/template/thinking masks must match the original experiment. Their optimizer grouping remains the only training-setting difference between the two MMuse entrypoints.

| Run            | Architecture                                        | Markov optimizer | Markov LR / weight decay |
| -------------- | --------------------------------------------------- | ---------------- | ------------------------ |
| DSpark custom  | Baseline Markov + confidence; four script overrides | Muon             | 6e-4 / 0                 |
| MMuse legacy   | Supplied bestarch                                   | Muon             | 6e-4 / 0.1               |
| MMuse upstream | Identical bestarch                                  | AdamW            | 6e-5 / 0.01              |

The pasted trainer has `LR=6e-5` and no explicit optimizer; the historical parser defaults to Muon with `muon_lr=10*lr`. The server's unused LR variable does not control training. Both MMuse runs explicitly keep backbone Muon LR=6e-4 and base AdamW LR=6e-5. Only `--muon-parameter-policy legacy/upstream` changes, moving Markov factors between these groups (including the corresponding LR/weight decay). This is a **grouping-policy comparison**, not a pure optimizer-algorithm comparison with equal hyperparameters. It does not activate the full upstream recipe, change Markov initialization to std=0.01, enable fused losses, or apply proposed PR #1066. Unspecified policies elsewhere retain the previous training-recipe behavior.

The old enhanced `dspark` model is now called `mmuse`. Both MMuse scripts preserve Correction logits mode (768 hidden / rank 256), auxiliary hidden supervision, hidden feedback, dual projection, Markov collaboration, context residual, block-position embeddings, gated layer fusion, dynamic convolution and the greedy top-16 Selector with corrected feedback and selector loss weight 0.1. No Correction MoE or DFly/KV-projection experiment is added to this recipe.

The supplied script omitted `--draft-vocab-size`. The default here does too: existing `d2t.npy`/`t2d.npy` are reused, otherwise the full vocabulary is used. Use the same dataset/mapping files for the two MMuse runs. Set `DRAFT_VOCAB_SIZE` only if the historical run actually used an explicit size; 32k is not imposed. DSpark uses the same original mapping-cache policy, not a forced full vocabulary. New backend/distributed changes mean this is not proof of pre-refactor bitwise parity.

## Inspect without training

```bash
DRY_RUN=1 bash examples/train/qwen3_4b_bestarch/server.sh
DUMP_CONFIG=1 bash examples/train/qwen3_4b_bestarch/train_dspark.sh
DRY_RUN=1 bash examples/train/qwen3_4b_bestarch/train_mmuse_upstream_optimizer.sh
DUMP_CONFIG=1 bash examples/train/qwen3_4b_bestarch/train_mmuse_upstream_optimizer.sh
```

Dry runs print commands without creating output directories, starting a server or training. `DUMP_CONFIG=1` uses the real configuration parser without loading weights or requiring a live target, and requires the normal Python package dependencies. For repeats, for example:

```bash
OUTPUT_DIR=./output/qwen3_4b_bestarch/repeat_legacy \
    bash examples/train/qwen3_4b_bestarch/train_mmuse_legacy_optimizer.sh
```
